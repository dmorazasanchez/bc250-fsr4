# BC-250 FSR4 v2 — selective signed DP4A lowering

This branch contains the second BC-250 / GFX1013 FSR4 optimization.

## Base

- Mesa 26.2.0
- BC-250 GFX1013 compute-queue base fix
- optional `RADV_GFX103=1` override (off by default)
- FSR4 signed 4x8 software DP4A optimization

Mesa 26.2 already uses `imul24_relaxed` for the software signed 4x8 dot-product fallback. The original v1-style reassociation is very effective on most FSR4 kernels, but corpus profiling found two pathological shader families where applying it globally greatly increases register pressure and spilling.

## v2 change

For `sdot_4x8_iadd`:

- constant accumulator `c` -> keep Mesa's balanced four-product sum
- non-constant accumulator `c` -> use the right-reassociated sum

The constant rule is intentionally placed before the generic rule in `nir_opt_algebraic.py`.

This preserves the major wins from reassociation while avoiding the worst spill regressions discovered in a 64-shader FSR4 capture.

## Runtime validation

Tested with FSR 4.1.1 in Cyberpunk 2077 on AMD BC-250 / GFX1013. In repeated same-scene testing, this v2 EXP-028 build performed better than the previous MastaG/global-reassociation baseline while rendering correctly.

Known-good local EXP-028 `libvulkan_radeon.so` SHA256:

    49f0ceb277e90734df1c1c6dcdfef2b871481da4bd32562ec397428492513af6

The binary itself is not committed; the repository builds it from Mesa 26.2.0 and the included patches.

## Build

From the `v2` branch:

    ./build-anywhere.sh

The patched variant applies, in order:

1. `v2-patches/0001-gfx1013-compute-queue-fix.patch`
2. `bc250-fsr4-v2-selective-sdot.patch`
3. `v2-patches/0003-radv-gfx103.patch`

Then run:

    ./setup.sh

Use the generated ICD with Steam, for example:

    VK_DRIVER_FILES=/absolute/path/radv-bc250-fsr4.json WINEDLLOVERRIDES="version=n,b" %command% --launcher-skip

Do not install the experimental RADV library system-wide.
